# Task 2.7 — Packet Analysis

## Introduction
Wireshark was used to capture and analyse authorised network traffic generated by the system. The captured traffic was examined to identify DNS, ICMP, TCP, HTTP, and TLS/HTTPS protocols and to understand how they are used during normal network communication.

## 1. DNS Analysis
A DNS packet was captured while accessing a website through a web browser.

|Item |	Value |
|---|---|
|Source IP |	192.168.222.36 |
|Destination IP |	192.168.222.165|
|Source Port |	52480 |
|Destination Port |	53 |
|Protocol |	DNS over UDP |
|Packet Length |	74 bytes |
|Information |	Standard query |

Analysis

The local system at 192.168.222.36 sent a DNS query to the DNS server at 192.168.222.165. The source port 52480 is a temporary client-side port, while destination port 53 is the standard port used by DNS.

## 2. ICMP Analysis

|Item |	Value |

## 3. TCP Three-Way Handshake
A TCP three-way handshake was identified in the Wireshark capture while accessing an HTTPS service.

TCP Connection Details

|Item |	Value |
|---|---|
|Source IP | 	192.168.222.36 |
|Destination IP	| 20.184.175.17 |
|Protocol |	TCP |
|Source Port |	60257 |
|Destination Port |	443 |

Packet Sequence

| Step	| TCP Flag	Source |	Destination |
|---|---|---|
|1	SYN	| 192.168.222.36:60257 |	20.184.175.17:443 |
|2	SYN, ACK |	20.184.175.17:443 |	192.168.222.36:60257 |
|3	ACK	| 192.168.222.36:60257	| 20.184.175.17:443 |

Analysis

The three packets demonstrate the normal TCP connection-establishment process: SYN → SYN, ACK → ACK.

The client first sends a SYN request to establish a connection. The server responds with a SYN, ACK, and the client sends the final ACK to confirm the connection. Port 443 is associated with HTTPS traffic, while 60257 is a temporary client-side port.

Evidence: screenshots/wireshark-tcp-three-way handshake.png

## 5. TLS/HTTPS Analysis
TLS traffic was identified in the Wireshark capture while accessing a secure web service. A TLS 1.3 Client Hello packet was observed.

TLS Packet Details

* Source IP:192.168.222.36

* Destination IP:104.20.23.154

* Source Port:54784

* Destination Port:	443

* Protocol:	TLSv1.3

* Packet Length:637 bytes

* TLS Message:Client Hello

Analysis

The Client Hello is part of the TLS connection-establishment process. The client sends it to the server to begin negotiating a secure connection. Destination port 443 is the standard port used for HTTPS.

The capture also contained Server Hello and Application Data TLS packets, showing that TLS traffic was exchanged between the client and server.

Evidence: screenshots/wireshark-tls-https.png

## 6. Packet Analysis Summary
Wireshark was used to capture and analyse authorised network traffic generated by the system. The analysis identified DNS, ICMP, TCP, HTTP, and TLS/HTTPS traffic.

The DNS analysis showed a DNS query from the local system to the configured DNS server. ICMP traffic was observed when testing connectivity to an external IP address. A complete TCP three-way handshake was identified using the sequence SYN → SYN, ACK → ACK.

HTTP analysis identified a GET request sent to a web server over destination port 80. TLS analysis identified a TLS 1.3 Client Hello sent to destination port 443, along with Server Hello and Application Data packets.

These observations demonstrate how different network protocols operate during normal network communication and provide practical evidence of packet-level network analysis using Wireshark.
